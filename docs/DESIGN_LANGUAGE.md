# UI 设计语言

本文档是 SamsTownWeb 的视觉事实与修改约束。任何页面、组件、样式、素材、动效或响应式变化都必须先阅读本文件，并在规则变化时同步更新。

## 1. 设计定位

关键词：暖棕、典雅、克制、沉浸、Minecraft 社区、人情味。

界面应像一本被暖光照亮的社区档案，而不是霓虹游戏启动器或通用 SaaS 后台。视觉重点来自真实社区图片、琥珀色引导、深色材质、适度留白和细腻动效。

公共品牌页与工具页使用同一套变量，但目标不同：

- 首页、历史：叙事、沉浸、媒体、呼吸感。
- 地图、后台：清晰、紧凑、状态明确、操作高效。
- 账号、对话框：降低干扰，强调步骤、错误和安全状态。

当前主页视觉规则：页面右侧不显示滚动条，`一路走来` 时间轴保留可见的横向滚动条；Hero 到浅色内容区使用同色纸张过渡，不使用灰褐色断层。Hero 的“加入我们”和“小镇档案”共用从中间向两侧展开的下划线控件，其他 `text-action` 也使用同一动画。

## 2. 事实来源

- 全局变量和基础组件：`src/styles/global.css`
- 视觉细节、首页、地图和页面优化：`src/styles/polish.css`
- 漂移照片墙：`src/styles/drift-wall.css`
- 深浅主题状态：`src/theme/ThemeContext.tsx`
- 首屏主题预置：`public/theme-init.js`
- 滚动渐显：`src/hooks/useScrollReveal.ts`
- Hero 过渡：`src/components/HeroTransition.tsx`

不要在组件内新建第二套颜色系统。新 token 先加入 `global.css` 的两个主题，再在组件中引用。

## 3. 色彩系统

### 深色主题

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#211c18` | 页面主背景 |
| `--surface` | `#2a241f` | 卡片、侧栏、主体表面 |
| `--surface-2` | `#352d26` | 次级层级和悬停表面 |
| `--text` | `#f0e4d1` | 正文 |
| `--text-strong` | `#fff2dd` | 标题和强信息 |
| `--text-soft` | `#d6c5ae` | 次级说明 |
| `--amber` | `#d38d42` | 主操作、选中、重点和品牌光 |
| `--earth` | `#956740` | 土色辅助 |
| `--line` | `rgba(222,191,149,.14)` | 轻分隔线 |
| `--danger` | `#ff9da5` | 危险和错误 |

### 浅色主题

浅色不是纯白反色，而是纸张和木质感：

| Token | 值 |
| --- | --- |
| `--bg` | `#eee2cb` |
| `--surface` | `#f7edd9` |
| `--surface-2` | `#e2d0b2` |
| `--text` | `#3a2a1d` |
| `--text-strong` | `#281a11` |
| `--text-soft` | `#584636` |
| `--amber` | `#8a4d20` |
| `--muted` | `#6f5947` |

要求：

- 颜色必须使用语义 token，不直接复制十六进制值到新组件。
- 媒体上的文字使用 `--on-media`/`--on-media-soft`，不要受页面浅色主题影响而失去对比。
- 浮层使用 `--overlay-surface`，输入使用 `--input-bg`，交互悬停使用 `--control-hover` 或 `--interactive-surface-hover`。
- 危险按钮保持危险色语义，不能因品牌统一改成琥珀色。
- 透明度和 `color-mix()` 用于层次，不用高饱和渐变制造新视觉中心。

## 4. 排版

- 正文：`"Noto Sans SC", system-ui, sans-serif`。
- 一级标题：`"Playfair Display", "Noto Sans SC", serif`。
- 英文 eyebrow、小标签和编号可使用大写、字距和较小字号。
- 中文正文保持自然字距，不对长段中文应用夸张 `letter-spacing`。
- 标题层级依靠字号、字重、留白和颜色共同表达，不只靠加粗。
- 用户可见文案从 `src/i18n/` 读取；不要把中英文句子硬编码到视觉组件。

## 5. 空间、形状与层级

- 页面最小宽度为 320px。
- 公共内容段落使用宽阔纵向间距；工具页减少无效留白。
- 全局大卡片圆角基准 `--radius: 22px`；输入和紧凑控件使用约 9–13px。
- Modal 使用更明确的 24px 圆角和高层阴影。
- 细边框承担分组，阴影承担浮层；普通卡片不要同时使用重边框和重阴影。
- 浮层阴影使用 `--shadow-float`；媒体使用 `--media-shadow` 和 `--media-shadow-hover`。
- 装饰菱形、暖光和纸张颗粒只能作为背景，不得降低文字可读性或抢占点击事件。

## 6. 组件规范

### 按钮

普通动作使用 `Button`，图标动作用 `IconButton`，保存使用 `SaveButton`；共享模块管理图标、忙碌状态和默认按钮类型。

- 主按钮使用 `--amber` 背景和 `--on-primary` 前景；深浅主题分别定义文字色，普通文字对比度至少 4.5:1。
- 次按钮使用透明/表面背景、语义边框和正文色。
- Hover 可轻微放大并增加琥珀光；Active 缩小形成按压反馈。
- Disabled 必须同时有视觉弱化和不可点击语义。
- 危险操作使用危险色，并在不可逆操作前要求明确确认。

### 输入与选择器

- 输入框沿用主题变量和统一 focus 样式。
- 选择器统一使用 `SelectField` 的原生 `select`，键盘与移动端交互交给浏览器。
- 表单错误统一使用 `Notice`，加载失败用 `RetryNotice`。

### 卡片与列表

- 卡片只在内容确实形成独立对象时使用，避免“卡片套卡片”。
- 列表优先用分隔、层次和对齐表达关系。
- 可编辑对象必须让所有者、状态、更新时间和操作入口清晰可见。
- Loading、Empty、Error、Success 四类状态都要设计，不允许只有成功态。

### 对话框

- 业务对话框使用原生 `Dialog`，统一顶层展示、焦点隔离／恢复、Escape 和遮罩关闭。
- 编辑动作区使用 `DialogActions`，二次确认使用 `ConfirmDialog`。
- 忙碌或强制改密时用 `dismissible={false}`。
- CSS 使用 `.modal` 与 `.modal::backdrop`，适配小屏和减少动效偏好。

### 媒体

- 使用 `TownImage`、`TownMedia`、`MediaFigure` 统一加载、失败回退和说明。
- 图片保持内容主体，不叠加厚重边框。
- 图片说明默认收敛，在 Hover/Focus 等明确交互中展示；移动端需有等价可访问方式。
- 漂移照片墙进入焦点浏览时使用稳定、可滚动的静态布局，焦点对象须在墙内可见；离开后恢复漂移。克隆不得重复进入 Tab，减少动效模式始终使用静态布局。
- 只使用仓库已有授权素材或明确允许的新素材。
- Vite 只复制 `images/optimized/`；不要恢复已移除的原始大图路径。

## 7. 页面模式

### 首页

- Hero 是唯一首屏视觉中心：背景媒体、深色渐变、短标题和明确 CTA。
- 文案按 eyebrow → H1 → 描述 → 按钮顺序分段进入。
- 内容遵循叙事节奏：介绍、理由、图集、成员、历史、加入、FAQ、公告。
- 固定快捷导航只在页面滚动到有效区间时出现，不遮挡主体。
- 桌面目录显示当前章节，使用 13px 无框文字和轻弹出动效；手机改为可展开的文字目录，支持键盘操作和 Escape 关闭。页面和内部滚动区保留细滚动条，确保横向内容可发现。
- 浅色首屏仍使用深色文字承托遮罩，加入入口使用主按钮；手机单独设置媒体焦点。成员介绍正文至少 14px，FAQ 缩进随屏宽收敛。
- 浅色 Hero 底部必须自然融入 `--bg`，不得出现灰褐色横向色带；天数计时使用明亮琥珀色和暖光，避免低饱和灰字。
- 首页 section、内部文案组和左右媒体可分别渐显，但不能建立相互竞争的嵌套观察器。

### 历史页

- 以档案、时间线、成员和媒体为主，强调时间顺序。
- 长时间线需要清晰锚点和移动端可读宽度。

### 地图页

- 使用紧凑标题区，不占满首屏；桌面和移动首屏应出现工作区入口，不把工具操作放在沉浸式展示 Hero 之后。

- 地图画布优先占据空间，侧栏和工具条保持紧凑。
- 工作区高度有界：桌面 `clamp(400px,100svh - 350px,860px)`，小屏 `clamp(360px,100svh - 340px,680px)`。紧凑标题、工作区和工具条共同适配首屏；长列表内部滚动，不能撑成数屏画布。此规则替代旧的桌面 640px/手机 680px 最小高度。
- Claim 颜色属于用户数据；UI 需保证边界、填充和标签共同表达。
- Marker 使用菱形视觉和类型图标，不与 Claim 混淆。
- 地图 Hover 信息卡不可拦截画布操作。
- 认领名称保持固定屏幕字号，不随地图高倍放大占满画布；字号由 `atlasConfig.claimLabelScreenSize` 校验。裁剪后的片段不显示误导性轮廓和名称。
- 离线、加载、空地图、无权限和保存冲突必须有明确状态。
- 数据加载错误放在工作区上方的独立区域，不与地图标签或工具条重叠；面向访客的提示说明恢复方式，不暴露数据库迁移术语。
- 手机出现工作区上方的错误提示时，画布高度预算额外预留 100px，仍保留 360px 最小高度；极矮视口允许页面纵向滚动。
- 低倍地图显示分块占用概览，放大后展示精确认领格。概览须有文字标识，不能直接用于认领。
- 未加载区域有明确遮罩，加载失败可重试；未加载不能被理解为空闲，数据未就绪时禁止写入。
- 认领列表保留全图搜索和独立分页；定位、数量使用完整摘要，不能按视口内格子计算。

### 后台

- 优先可扫描性：稳定列宽、分组标题、紧凑工具栏和明确批量操作。
- Sticky 区域必须在小屏退化为普通流式布局。
- 横向滚动只能用于无法合理折叠的数据，不得造成整个页面横向溢出。

## 8. 动效

核心变量：

```css
--ease-out: cubic-bezier(.22,1,.36,1);
--ease-spring: cubic-bezier(.34,1.56,.64,1);
--motion-fast: .2s;
--motion-base: .3s;
--motion-slow: .5s;
```

允许的动效：

- 首屏 Terrain Loading 和 App Ready 淡入。
- Hero 文字分段进入与角色/媒体进入。
- 内容滚动渐显，组内以 80ms 为单位有限错峰。
- 按钮 Hover/Active、导航下划线、对话框进入。
- 地图 Marker 呼吸和当前选择边界提示。

限制：

- 动效服务于层级、方向和反馈，不循环制造噪声。
- 滚动渐显最终必须可见；Observer 失败或用户跳转锚点不能留下 `opacity: 0`。
- 首页左右媒体初始水平位移保持克制，避免瞬时横向溢出。
- FAQ 外层 section 可渐显，FAQ item 不再建立嵌套滚动渐显。
- 所有动效必须适配：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto !important;
    animation: none !important;
    transition-duration: .01ms !important;
  }
}
```

## 9. 响应式

- 从内容需要出发设置断点，不按设备品牌设置。
- 桌面中央导航在窄屏切换为移动菜单；品牌和关键操作不能被挤出。
- 小屏语言切换进入菜单；页头、手机菜单和页脚不提供博客跳转。
- 两栏故事、账号身份、后台和地图布局在小屏变为单列或抽屉式结构。
- 触控目标至少 40px，主要图标控件至少 44px，不能依赖 Hover 才能完成关键操作。
- 页面滚动条默认隐藏；只有具有独立横向内容的时间轴恢复可见滚动条，并提供键盘方向键操作。
- 正文、表单和对话框在 320px 宽度下不得横向裁切。
- 桌面和移动端都不得出现页面级水平滚动。

## 10. 无障碍

- 所有交互使用原生 `button`、`a`、`input` 等语义元素。
- 照片墙卡片使用原生按钮，支持 Enter/Space 和可见焦点；重复副本不重复进入键盘顺序。
- 仅键盘焦点进入照片墙静态可滚动布局；鼠标或触屏点击重复副本不得隐藏当前卡片，减少动态偏好仍使用静态布局。
- 菜单通过 Escape 关闭后，焦点返回打开菜单的按钮。
- 键盘焦点必须清晰；不能用 `outline: none` 后不提供替代。
- 图标按钮提供可访问名称，装饰图标隐藏于辅助技术。
- 表单字段有 label，错误与字段建立关联。
- 颜色不是唯一状态信号；配合文字、图标、边框或形状。
- 主题切换、菜单、Tab、Dialog 和 Accordion 保持正确 ARIA 状态。
- 媒体提供有意义的 alt；纯装饰图像使用空 alt。

## 11. 修改流程与视觉验收

视觉改动前：

1. 查看真实页面和目标断点。
2. 确认现有 DOM、素材、主题和交互契约。
3. 优先复用 token、组件和模式。

最小验收：

- 深色和浅色主题。
- 典型桌面宽度与 320–390px 移动宽度。
- 键盘 Focus 和触控操作。
- Loading、Empty、Error 和长文本。
- `prefers-reduced-motion`。
- 无页面级水平溢出、无控制台错误。

构建和单元测试通过不等于视觉验收完成；必须检查真实渲染。

## 12. 禁止事项

- 不引入第二套 CSS 框架或组件库替换现有设计系统。
- 不在 JSX 中散落固定颜色、阴影和动画时长。
- 不把公共品牌页改成密集后台布局，也不把工具页做成低效率展示页。
- 不删除既有素材、交互或主题支持来换取表面简化。
- 不使用过量毛玻璃、霓虹、纯黑、纯白或高饱和电竞渐变。
- 不以隐藏滚动条为理由破坏键盘、滚轮或触控滚动。
